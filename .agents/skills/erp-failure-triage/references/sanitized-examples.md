# 脱敏示例

以下示例仅演示分析方法，来自阶段开发用脱敏材料。它们不得作为其他案例的事实来源，也不得作为后续未见样本。

## 示例一：负向断言与实际响应冲突

### 输入事实

- 测试准备库存为 100，并尝试以数量 99999 创建销售出库。
- 测试期望响应 code 不等于 200，实际响应 code 为 200。
- 后续摘要记录有效单据数量期望为 0、实际为 1。
- 没有提供独立确认的“超库存必须拒绝”产品规则。

### 合规分析

- 已确认事实：测试的负向断言失败，且脱敏摘要记录了与预期不同的单据数量。
- 主分类：产品行为或接口契约问题（契约待确认）。
- 候选根因：测试预期与当前接口行为或尚未确认的产品契约不一致，置信度中。
- 不能得出的结论：已确认产品缺陷。
- 最小补证：正式规则依据，以及能以运行 ID、测试节点和业务对象关联的脱敏请求、响应与单据查询摘要。

## 示例二：销售 E2E 库存断言失败

### 输入事实

- 用例声明销售数量为 1。
- 脱敏摘要中的初始库存为 198，操作后库存为 187；测试期望为 197。
- 流程摘要为 UI 创建、审核，再进行库存断言。
- 没有提供保存请求中的数量、持久化明细数量、UI 实际输入值、对象关联信息或并发操作证据。

### 合规分析

- 已确认事实：库存实际减少 11，与用例声明数量 1 对应的预期不一致。
- 主分类：证据不足，暂无法分类。
- 候选根因不超过三个：提交或持久化数量不同、同一库存受其他操作影响、库存断言关联了错误的对象或基线；置信度均为低。
- 不能得出的结论：某个字符被追加、某个 UI 控件必然有缺陷，或具体代码已经修复。
- 最小补证：同一次执行的 UI 输入摘要、保存请求数量、持久化明细数量、库存查询对象与时间，以及运行 ID/单据号关联。
